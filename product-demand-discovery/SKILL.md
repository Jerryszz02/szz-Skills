# 产品需求发现

发现可验证的产品机会，给出证据、市场估算、风险与下一步验证实验。默认输出中文，结论与来源可对应。

## 研究范围

从请求提取领域、地区、语言、目标用户和市场目标。用户未指定时，默认研究全球、中英文公开信息中的互联网软件与 AI 工具，面向独立开发者到小团队可执行的轻量 SaaS、插件和垂直工作流；开始时简短说明采用的默认范围。

## 工作流与按需资源

1. 检查当前工作目录的 `outputs/product-demand-discovery/index.json`。用户指定输出目录时在该目录检查索引。有相关历史时读取最近报告，并按 [输出规则](references/output-schema.md) 识别已有机会；索引不存在时继续研究。
2. 选择来源与搜索词时读取 [信息源分层与搜索矩阵](references/source-taxonomy.md)。围绕痛点、竞品和市场信号组合查询，依据已找到的证据调整，避免机械执行所有示例词。
3. 按下方工具规则搜索并读取正文。每条证据记录 URL、平台、发布日期或检索日期、作者或组织、摘要、痛点、替代方案、付费意图和相关竞品。
4. 按 `target_user + job_to_be_done + core_pain_cluster` 合并需求。同一作者、转载或相同素材只算一个独立来源。
5. 对候选检查直接竞品、替代方案、差评与应用商店等供给信息。Product Hunt 只证明新品供给信号，不单独证明需求。
6. 进入市场估算和评分时读取 [评分规则](references/scoring-rules.md)，沿用独立证据、来源覆盖、竞品定义和分项阈值。缺证据时标为观察或覆盖不足，不以低覆盖结果冒充完整验证。
7. 交付前读取 [输出规则](references/output-schema.md)，写入 Markdown 报告与索引；保存位置、字段及历史去重以该文件为准。用户明确只要对话结果或禁止写文件时，在对话交付并说明未更新历史索引。

## 工具选择与降级

- 优先使用当前宿主实际提供的 Firecrawl 搜索、抓取和抽取能力。先发现工具并读取参数说明，不假设某个工具名称或反馈接口必然存在。
- Firecrawl 缺失、限流或无法读取某页时，可使用宿主已有的网页搜索、页面打开或浏览器工具。搜索用于发现链接；只有读到可核验正文的页面才计入证据。更换工具不降低证据门槛。
- 只读当前任务相关的公开页面。不得因降级自行安装插件、申请凭据、启动付费服务或上传本地私有内容。
- 所有可用读取途径均失败时，报告未完成的来源覆盖、候选验证与下一步可行检查；不编造正文或来源。

## 交付

先给结论，再给支持结论的证据。每项说明目标用户、痛点、当前替代方案、竞品缺口与数量、市场估算、Demand / Market / Gap / Overall、来源、风险、下一步实验及历史去重状态。

候选分为 `推荐`、`观察`、`淘汰`。推荐须满足评分规则中的全部门槛；观察表示证据不足或有待验证，不能写成已经证明可行。

## 边界

- 不绕过登录墙、验证码、付费墙、地区限制或反爬机制。
- 不读取或要求 Cookie、账号密码、私有 API key、付费数据库或浏览器隐私数据。
- 不把榜单排名、点赞、媒体曝光、融资新闻或 Product Hunt 票数当作独立需求证明。
- 区分已知数据、估算假设与推断；没有足够证据时交付覆盖缺口，不强行推荐。
