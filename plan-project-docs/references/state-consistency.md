# 状态与一致性审计

更新或审计已有项目文档时，使用本规则区分计划、当前事实和历史证据，并完成跨文档检查。

## 证据优先级

同一状态出现冲突时，按以下顺序判断；高优先级证据仍需与本次任务时间相关：

1. 本次安全执行的运行时、部署/provider 或公开端点探针；
2. 当前代码、配置、schema、Git 状态和实际文件；
3. 本次运行的自动化测试、构建或静态检查；
4. 带日期、可定位到原始输出的历史日志或验收 artifact；
5. 项目文档、README 和注释；
6. 正式 plan、会话上下文或记忆。

低优先级来源可以定义目标或提示检查方向，不能覆盖更高优先级的当前证据。外部状态需要凭据且无法安全访问时，不要猜测；写明最后验证时间和缺少的验证入口。

## 状态标签

| 标签 | 使用条件 |
| --- | --- |
| `计划中` | 只在认可的 plan 中存在，尚无实现证据 |
| `已实现未验证` | 代码或配置已存在，但相关检查未运行或失败 |
| `已验证` | 本次或明确带日期的相关检查通过 |
| `已部署` | 本次 provider/公开端点或可定位部署输出证明已上线 |
| `已暂停` | 工作暂时停止，恢复条件仍存在 |
| `已取消` | 用户或权威决策明确不再要求；不得继续列为当前必做门 |
| `历史记录` | 只描述过去某次运行、部署或决策，不作为当前状态 |
| `待确认` | 当前证据不足或互相冲突 |

不要用“完成”“可用”“生产正常”等宽泛词同时代替实现、验证和部署三个不同状态。

## 更新前漂移清单

先从已有文档提取并核对：

- 项目/模块/skill 数量、名称和路径；
- 当前能力、未实现项和非目标；
- 测试命令、测试数量、构建结果和人工验收；
- API、schema、持久化和安全边界；
- 发布平台、部署地址、自动部署和运行任务；
- 暂停、取消、完成、回滚和验收门；
- `docs/planning/README.md` 的已生成、已跳过与待确认表。

查看相关 Git log/diff，识别文档上次更新时间之后的实现、删除、重命名、测试、发布或决策变化。只看当前文件树会遗漏“为什么状态变了”，只看 Git 历史会遗漏未提交的当前工作区。

## 状态变化处理

- **计划已实现**：把目标条目改为 `已实现未验证`；检查通过后再改为 `已验证`。
- **测试后来执行**：更新索引、测试计划和根 README 中的旧“未执行”表述；记录本次或准确历史日期。
- **进入发布阶段**：重新评估 `release-plan.md`；已有 `docs/app-store/`、部署清单或 runbook 时可直接链接，不重复创建。
- **模块重命名或删除**：搜索旧名称在所有维护文档中的残留，并说明兼容或迁移边界。
- **任务暂停或取消**：把仍有长期价值的验收设计标为“可复用方案”，删除其当前必做语气；历史运行日志标为历史。
- **deployment 改变**：旧部署证据继续是历史，不能证明当前 alias、版本或自动部署正常。
- **分支与生产不一致**：功能或文档只存在于 feature branch 时，不得写成默认分支或生产现状；核对当前分支、upstream、部署分支和公开产物。
- **新增 planning 文件**：必须加入索引，并重新评估与既有文件的重复关系。

## 历史与当前状态隔离

长期 planning 文档适合保存稳定需求、设计约束、测试策略和发布方法。以下内容容易过期，默认放在 dated artifact、运行日志或运维系统中：

- 单次 deployment ID、report ID、run ID；
- 逐槽 burn-in/soak 记录；
- 临时 observer、LaunchAgent 或心跳状态；
- 某天的线上数量、延迟或健康快照；
- 已被后续决策替代的调试叙事。

如果仓库已经把这些内容放在 `docs/planning/`：

1. 在文件顶部标记 `历史记录`、覆盖日期和“不作为当前状态来源”；
2. 在索引指向当前状态的权威来源；
3. 不在文件尾继续追加一个与前文“进行中”冲突的“已取消”；必要时重构历史摘要。

## 跨文档一致性检查

完成编辑后至少检查：

1. 索引列出的 planning 文件与磁盘一致；新增文件没有漏列。
2. 已跳过理由仍符合当前范围；发布、数据库、API 或运维出现后已重新分类。
3. 同一事项没有同时出现“未执行/已通过”“进行中/已取消”“未来计划/当前实现”。
4. 根 README、planning 索引、PRD、技术设计、测试计划和发布文档使用一致的模块名称与状态。
5. 测试命令、路径、版本和数量与本次实际检查一致；未执行项明确标记。
6. 外部链接与部署事实带验证日期；旧部署输出不被称为当前。
7. 当前分支、upstream、默认分支和部署产物没有被混成同一个状态。
8. 计划目标与实现事实分开，未因 plan 文字而提前宣布完成。
9. dated 历史记录不再承担当前状态页职责。

可先用 `rg` 搜索项目特有的旧名称、日期、状态词和关键数字，再运行 `scripts/audit_planning_docs.py` 检查索引覆盖与链接。脚本通过不代表语义一致性已经通过。
